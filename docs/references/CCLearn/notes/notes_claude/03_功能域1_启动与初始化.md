## 二、文件清单与逐文件分析

### 文件 1: `entrypoints/cli.tsx` (302行)

**角色**: 整个 Claude Code 的**第一个入口文件**，所有执行路径的大门。

**核心职责**: 以最少的模块加载，将不同的 CLI 调用快速分发到各自的处理路径。

**关键设计**: 极致的启动速度优化 — `--version` 路径零导入，其他路径按需动态 import。

**内部逻辑逐段解析**:

```
行 1-26: 顶层副作用（import 前执行）
├── process.env.COREPACK_ENABLE_AUTO_PIN = '0' — 修 corepack 的 bug
├── CLAUDE_CODE_REMOTE === 'true' → 设 NODE_OPTIONS max-old-space-size=8192 (CCR 容器 16GB)
└── feature('ABLATION_BASELINE') → 消融实验基线（禁用 thinking/compact/memory 等）

行 33-42: main() 函数开始
├── 解析 process.argv.slice(2)
└── 快速路径 1: --version/-v → 直接 console.log(MACRO.VERSION)，零导入返回

行 44-71: 其他快速路径（每个都是独立的 await import + 执行 + return）
├── 快速路径 2: --dump-system-prompt → 输出渲染后的系统提示词（Ant 内部 eval 用）
├── 快速路径 3: --claude-in-chrome-mcp → Chrome 扩展 MCP 服务器
├── 快速路径 4: --chrome-native-host → Chrome 原生消息主机
└── 快速路径 5: --computer-use-mcp → Computer Use MCP（feature gate: CHICAGO_MCP）

行 100-161: 功能性快速路径
├── 快速路径 6: --daemon-worker → 守护进程工作线程
├── 快速路径 7: remote-control/rc/remote/sync/bridge → Bridge 远程控制模式
│   ├── enableConfigs()
│   ├── 认证检查（OAuth token）

│   └── bridgeMain(args) → 进入 bridge 主循环
├── 快速路径 8: daemon → 守护进程管理
└── 快速路径 9: ps/logs/attach/kill/--bg → 后台会话管理

行 212-245: 更多快速路径
├── 快速路径 10: new/list/reply → 模板任务（feature: TEMPLATES）

└── --tmux + --worktree → exec 到 tmux 会话中

行 288-301: 默认路径 → 加载完整 CLI
├── profileCheckpoint('cli_before_main_import')
├── const { main } = await import('../main.js')  ← 动态导入 main.tsx
├── await main()  ← 执行主函数
└── profileCheckpoint('cli_after_main_complete')
```

**关键洞察**:
- 共 12+ 个快速路径，每个都避免加载完整的 main.tsx（13万+ 行的导入链）
- `feature()` 来自 `bun:bundle`，是**编译时**门控，外部构建直接删除整个代码块
- 只有**默认路径**（无特殊子命令）才会加载 main.tsx

- 交互模式 vs 非交互模式的分流点在 `run()` 函数内部
- 11 个迁移脚本**每次启动都执行**（每个内部有幂等守卫）

### 文件 3: `entrypoints/init.ts` (341行)

**角色**: 配置/认证/网络/遥测的初始化器，被 main.tsx 的 `preAction` hook 调用。

**核心职责**: 在任何 CLI 命令执行前，确保环境就绪。

**`init()` 函数流程**（用 `memoize` 包裹，保证只执行一次）:

```
init() [memoized]:
├── [1] enableConfigs()  ← 验证并启用配置系统（utils/config.ts）
├── [2] applySafeConfigEnvironmentVariables()  ← 应用安全环境变量（不含信任敏感项）
├── [3] applyExtraCACertsFromConfig()  ← 应用 TLS CA 证书（必须在首次 TLS 前）
├── [4] setupGracefulShutdown()  ← 注册退出清理钩子
├── [5] initialize1PEventLogging()  ← 第一方事件日志（延迟加载 OpenTelemetry）
├── [6] populateOAuthAccountInfoIfNeeded()  ← 补充 OAuth 账户信息（异步）
├── [7] initJetBrainsDetection()  ← JetBrains IDE 检测（异步）
├── [8] detectCurrentRepository()  ← GitHub 仓库检测（异步）
├── [9] initializeRemoteManagedSettingsLoadingPromise()  ← 远程托管设置（如果有资格）
├── [10] initializePolicyLimitsLoadingPromise()  ← 策略限制（如果有资格）
├── [11] recordFirstStartTime()  ← 记录首次启动时间
├── [12] configureGlobalMTLS()  ← 配置 mTLS
├── [13] configureGlobalAgents()  ← 配置 HTTP 代理
├── [14] preconnectAnthropicApi()  ← 预连接 API（TCP+TLS 握手与后续工作并行）
├── [15] initUpstreamProxy()  ← CCR 环境上游代理（条件）
├── [16] setShellIfWindows()  ← Windows 下设置 git-bash
├── [17] registerCleanup(shutdownLspServerManager)  ← LSP 清理
├── [18] registerCleanup(cleanupSessionTeams)  ← 团队清理
└── [19] ensureScratchpadDir()  ← 创建暂存目录（如果启用）

错误处理:
├── ConfigParseError → 非交互模式打印 stderr，交互模式弹 InvalidConfigDialog
└── 其他错误 → 直接 rethrow
```

**`initializeTelemetryAfterTrust()` 函数**: 在用户接受信任对话框后初始化遥测
```
├── 如果有远程托管设置资格:
│   ├── 等待远程设置加载完成
│   ├── 重新应用环境变量（含远程设置）
│   └── doInitializeTelemetry()
└── 否则: 直接 doInitializeTelemetry()

doInitializeTelemetry():
├── 防重复执行守卫
├── 延迟加载 ~400KB OpenTelemetry + protobuf 模块
└── initializeTelemetry() → setMeter() → 创建 AttributedCounter 工厂
```

**关键洞察**:
- `memoize` 包裹确保 `init()` 只执行一次，即使被多处调用
- 步骤 5-8 全部用 `void` fire-and-forget，不阻塞启动
- 步骤 14 的 `preconnectAnthropicApi()` 是性能优化亮点：在 init 期间预连接 API，省去后续 100-200ms 的 TCP+TLS 握手
- 遥测延迟到信任对话框之后，避免未授权情况下发送数据

### 文件 4: `entrypoints/mcp.ts` (197行)

**角色**: Claude Code 作为 MCP Server 运行时的入口。

**核心职责**: 暴露 Claude Code 的所有工具为 MCP 工具，通过 stdio 传输协议对外服务。

**内部逻辑**:

```
startMCPServer(cwd, debug, verbose):
├── 创建 readFileStateCache (LRU, 100文件限制)
├── 创建 MCP Server 实例 { name: 'claude/tengu', version: MACRO.VERSION }
│
├── ListToolsRequestSchema handler:
│   ├── getTools(emptyPermissionContext) → 获取所有工具
│   ├── 对每个 tool:
│   │   ├── tool.prompt() → 获取工具描述
│   │   ├── zodToJsonSchema(tool.inputSchema) → 输入 schema 转换
│   │   └── zodToJsonSchema(tool.outputSchema) → 输出 schema（如果有）
│   └── 返回工具列表
│
├── CallToolRequestSchema handler:
│   ├── findToolByName(tools, name)
│   ├── 构建简化的 ToolUseContext (无权限, 非交互, 无 MCP 客户端)
│   ├── tool.validateInput()
│   ├── tool.call() → 执行工具
│   └── 返回 { content: [{type:'text', text: result}] }
│
└── runServer():
    ├── new StdioServerTransport()
    └── server.connect(transport)  ← stdio 通信
```

**关键洞察**:
- MCP 模式下**无权限检查** (`getEmptyToolPermissionContext`)
- 没有交互能力 (`isNonInteractiveSession: true`)
- 只暴露 `review` 命令作为 MCP_COMMANDS
- 使用简化的 ToolUseContext，所有回调都是空函数

## 五、关键设计决策与原因

### 决策 1: 极致的快速路径分发
**做法**: cli.tsx 中 12+ 个 `if/return` 快速路径
**原因**: main.tsx 的 ~200 行 import 需要 ~135ms。`--version` 应该 <5ms 返回。

### 决策 2: 顶层副作用启动并行子进程
**做法**: `startMdmRawRead()` 和 `startKeychainPrefetch()` 在 import 语句之前执行
**原因**: 子进程在 ~135ms 的 import 评估期间运行完毕，实现"免费"并行。

### 决策 3: 全局单例而非 DI
**做法**: `bootstrap/state.ts` 导出 150+ 个 getter/setter
**原因**: CLI 是单进程单会话，不需要 DI。但代码注释反复警告不要添加更多状态。

### 决策 4: 每次启动执行所有迁移
**做法**: 11 个 `migrate*()` 每次启动都调用
**原因**: 每个迁移内部有幂等守卫，调用成本极低（~1ms/个），避免遗漏。

### 决策 5: preAction hook 延迟初始化
**做法**: `program.hook('preAction', async () => { await init(); ... })`
**原因**: `--help` 不需要初始化配置/认证/遥测。只有实际执行命令时才初始化。

### 决策 6: API 预连接
**做法**: `preconnectAnthropicApi()` 在 init() 末尾 fire-and-forget
**原因**: TCP+TLS 握手 100-200ms，在 init 和 action 设置期间并行完成。
