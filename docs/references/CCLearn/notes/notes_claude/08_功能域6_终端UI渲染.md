```

    │ DOMElement: { nodeName, attributes, childNodes, style, dirty, ... }
```

## 四、渲染性能优化

```
关键性能优化点:

1. 双缓冲渲染 (renderer.ts)
   ├── frontFrame / backFrame 交替
   ├── 只写入变化的单元格 (blit region)
   └── 避免全屏重绘

2. 行级字符缓存 (output.ts)
   ├── charCache: 不变的行不重新 tokenize
   ├── ClusteredChar 预计算: width + styleId + hyperlink
   └── 每帧热循环只做属性读取 + setCellAt

3. React Compiler 优化
   ├── 组件用 _c() (React Compiler runtime)
   ├── 细粒度 memo 化: 避免级联重渲染
   └── LogoHeader 用 React.memo 防止消息更新触发

4. 虚拟滚动 (VirtualMessageList.tsx)
   ├── 只渲染可见区域的消息
   ├── 上下预渲染缓冲区
   └── 长会话 (2800+ 消息) 性能关键

5. 脏节点追踪 (dom.ts)
   ├── dirty 标记: 只重新布局/渲染脏节点
   ├── markDirty() 向上传播
   └── seenDirtyChild 级联优化

6. 滚动节流 (dom.ts)
   ├── SCROLL_MAX_PER_FRAME: 每帧最多滚动 N 行
   ├── pendingScrollDelta: 累积未处理的滚动
   └── 快速滚动时显示中间帧

7. 内存池 (screen.ts)
   ├── CharPool: 字符复用
   ├── StylePool: 样式 ID 复用
   ├── HyperlinkPool: 超链接复用（5min 重置）
   └── 避免 GC 压力
```

## 六、关键设计决策

### 决策 1: 自定义 Ink 分支而非原版
**做法**: 完全 fork 了 Ink，实现了自研 DOM/layout/renderer
**原因**: 原版 Ink 不支持:
- 双缓冲渲染（性能关键）
- 虚拟滚动（长会话必需）
- 鼠标事件（点击/拖选）
- 文本选择和复制
- alt-screen 模式
- 搜索高亮
- 滚动节流

### 决策 2: 5005行的单一 REPL 组件
**做法**: 一个巨大的 React 组件管理所有状态
**原因**: REPL 的状态高度耦合（消息列表、查询状态、权限、工具、MCP 都互相影响）。拆分会导致大量 prop drilling 或 context 嵌套。460 个 hook 调用反映了真实的复杂度。

### 决策 3: React Compiler 优化
**做法**: 组件使用 `_c()` (React Compiler runtime) 而非手动 `useMemo/useCallback`
**原因**: 自动化的 memo 消除了人为遗漏的性能问题。LogoHeader 仍然用手动 `React.memo` 因为它是性能热点的起点。

### 决策 4: 内存池设计
**做法**: CharPool/StylePool/HyperlinkPool 在 screen.ts 中
**原因**: 终端渲染是高频操作。每帧数万个字符/样式对象如果都 GC 会导致卡顿。池化复用让 GC 压力接近零。

### 决策 5: 事件冒泡/捕获系统
**做法**: `ink/events/dispatcher.ts` 实现了 DOM 级别的事件分发
**原因**: 终端不像浏览器有原生事件系统。自建 dispatcher 让组件可以用 `onClick`/`onKeyDown` 等 React 风格 API。
