## 三、权限模式系统

### 3.1 六种权限模式

```
PermissionMode 枚举:

┌───────────┬──────────────┬────────────────────────────────────────┐
│ 模式       │ 符号          │ 行为                                   │
├───────────┼──────────────┼────────────────────────────────────────┤
│ default   │ (无)          │ 每次工具调用按规则判断，未匹配则询问用户 │
│ plan      │ ⏸ (暂停)      │ 只读操作允许，写入操作拒绝              │
│ acceptEdits│ ⏵⏵           │ 工作目录内的文件编辑自动允许            │
│ auto      │ ⏵⏵ (警告色)   │ AI 分类器自动决策（feature gate）       │
│ dontAsk   │ ⏵⏵ (危险色)   │ ask → 自动 deny（后台任务用）          │
│ bypass    │ ⏵⏵ (危险色)   │ 绕过所有权限检查                       │
└───────────┴──────────────┴────────────────────────────────────────┘

模式层次: bypass > auto > acceptEdits > default > plan
```

### 3.2 权限规则系统

```
PermissionRule 结构:
{
  source: PermissionRuleSource,   ← 规则来源
  ruleBehavior: 'allow'|'deny'|'ask',
  ruleValue: {
    toolName: string,             ← 工具名 (如 'Bash', 'Edit', 'mcp__server1')
    ruleContent?: string,         ← 可选的内容匹配 (如 'git *', '/path/to/file')
  }
}

规则来源优先级 (PERMISSION_RULE_SOURCES):
├── userSettings    ← ~/.claude/settings.json (用户级)
├── projectSettings ← .claude/settings.json (项目级)
├── localSettings   ← .claude/settings.local.json (本地级)
├── flagSettings    ← --settings flag
├── policySettings  ← 企业托管设置
├── cliArg          ← --allowedTools 命令行参数
├── command         ← 斜杠命令的 allowedTools
└── session         ← 会话内用户授权

规则匹配类型:
├── 工具级别: "Bash" → 匹配所有 Bash 调用
├── 前缀匹配: "Bash(git:*)" → 匹配 git 开头的命令
├── 通配符: "Bash(npm * --save)" → 模式匹配
├── 精确匹配: "Bash(ls -la)" → 精确命令
├── MCP 服务器级: "mcp__server1" → 匹配该服务器所有工具
└── Agent 类型: "Agent(Explore)" → 匹配特定 agent 类型
```

### 文件 5: `utils/permissions/yoloClassifier.ts` — AI 安全分类器

## 六、关键设计决策

### 决策 1: 多层防御 (Defense in Depth)
**做法**: 规则 → 工具特定 → hooks → 分类器/用户 → 沙箱
**原因**: 任何单一防线都可能被绕过。多层确保即使一层失效，其他层仍能保护。

### 决策 2: 失败关闭 (Fail-Closed)
**做法**: 分类器超时/错误 → deny，未知工具 → ask，解析失败 → ask
**原因**: 安全系统必须在不确定时拒绝，不能默认允许。

### 决策 3: 25+ 个 Bash 安全验证器
**做法**: 每个验证器检测一类特定的安全威胁
**原因**: Bash 是最危险的工具 — 可以执行任意命令。正则 + AST 双重检查确保覆盖面。每个验证器有唯一 ID（1-23），便于遥测追踪。

### 决策 4: 分类器降级安全阀
**做法**: 连续拒绝 3 次或总拒绝 20 次 → 降级到用户交互
**原因**: AI 分类器不是完美的。如果它持续拒绝正常操作，可能是误判。降级让用户有机会纠正。

### 决策 5: 危险模式预防
**做法**: 进入 auto 模式时自动剥离 `Bash(python:*)` 等危险 allow 规则
**原因**: `Bash(python:*)` 等于关闭了 Python 的安全检查。auto 模式不应继承这种过于宽泛的规则。

### 决策 6: 推测性分类器检查
**做法**: 在 pre-tool hooks 和 UI 准备期间就启动分类器
**原因**: 分类器需要 API 调用（~1s）。并行启动让用户看到对话框时，分类器结果已经就绪。

### 决策 7: Zsh 专属防御
**做法**: 20 个 Zsh 危险命令/模块的黑名单
**原因**: Zsh 有很多 Bash 没有的危险特性（zmodload, 进程替换, 内置文件操作）。用户 shell 可能是 Zsh。
