## 一、域概览

| 指标 | 值 |
|------|-----|
| 涉及文件 | ~30 个 |
| 总代码行数 | ~10,000 行 |
| 核心职责 | 连接外部 MCP 服务器，将其工具/资源/命令集成到 Claude Code |
| 关键设计模式 | 多传输协议、OAuth 认证、工具动态注册、并发连接管理 |

**MCP (Model Context Protocol) 是 Claude Code 的"外部扩展系统"** — 让第三方工具以标准协议接入。

## 四、MCP 工具名称规范化

```
MCP 服务器 "My Cool Server" 提供工具 "search-docs":

规范化流程:
├── 服务器名: normalizeNameForMCP("My Cool Server") → "my_cool_server"
├── 工具名: normalizeNameForMCP("search-docs") → "search_docs"
└── 最终名: buildMcpToolName("my_cool_server", "search_docs") → "mcp__my_cool_server__search_docs"

├── 工具级: "mcp__my_cool_server__search_docs" → 精确匹配
├── 服务器级: "mcp__my_cool_server" → 匹配该服务器所有工具
```

## 五、关键设计决策

### 决策 1: 模板工具克隆模式
**做法**: `MCPTool` 是一个模板，`fetchToolsForClient()` 为每个 MCP 工具克隆并覆盖方法
**原因**: 40+ MCP 工具不需要 40 个源文件。模板 + 运行时覆盖让所有 MCP 工具共享渲染和验证逻辑。

### 决策 2: 5 种配置来源合并
**做法**: settings → .mcp.json → 企业 → claude.ai → 插件 → 合并
**原因**: 不同角色（用户/项目/企业/云端）有不同的 MCP 需求。合并确保所有来源的服务器都可用。

### 决策 3: 认证缓存 (15min TTL)
**做法**: 401 响应后缓存 "needs-auth" 状态 15 分钟
**原因**: 频繁探测未授权的服务器浪费网络资源。15min TTL 让 print 模式不阻塞在无法成功的连接上。

### 决策 4: 本地/远程分批并发
**做法**: 本地服务器（stdio/sdk）低并发，远程服务器高并发
**原因**: stdio 需要 spawn 子进程，过多并发导致资源竞争。远程服务器只是网络连接，可以高并发。

### 决策 5: Elicitation 重试
**做法**: MCP -32042 错误 → 用户交互 → 重试工具调用
**原因**: 某些 MCP 服务器需要用户在浏览器中确认操作（如 OAuth 授权）。Elicitation 让工具调用可以"暂停等待用户"。

### 决策 6: 会话过期自动重连
**做法**: HTTP 404 + JSON-RPC -32001 → 清除缓存 → 重新连接 → 重试
**原因**: MCP 服务器可能重启或会话超时。自动重连让用户无感知。
