| 指标 | 值 |

## 三、7 种任务类型详解

### 类型 1: `LocalShellTask` (522行) — 后台 Shell 命令

```
LocalShellTaskState = TaskStateBase & {
  type: 'local_shell'
  command: string          ← 执行的 shell 命令
  pid?: number             ← 子进程 PID
  kind?: BashTaskKind      ← 'bash' | 'monitor'
  isBackgrounded: boolean  ← 是否已后台化
  toolUseId?: string       ← 关联的 tool_use ID
  agentId?: AgentId        ← 创建此任务的 agent
}

生命周期:
├── spawnShellTask(input, handle, ...) → 注册+启动
│   ├── registerTask(taskId, state, setAppState)
│   ├── handle: ShellCommand (子进程包装)
│   ├── 输出重定向到 taskOutputPath
│   └── startStallWatchdog() → 45s 无输出+像 prompt → 通知
├── backgroundExistingForegroundTask() → 前台→后台
├── registerForeground/unregisterForeground → 前台注册
├── 完成 → enqueueAgentNotification() → 通知主线程
└── killTask() → SIGTERM → SIGKILL

特殊功能: Stall 看门狗
├── 每 5s 检查输出文件大小
├── 45s 无增长 + 最后一行像交互提示 → 通知
├── 检测模式: (y/n), Press Enter, Continue?, Overwrite?
└── 防止命令阻塞在等待用户输入而无人知晓
```

### 类型 2: `LocalAgentTask` (682行) — 本地 Agent 任务

```
LocalAgentTaskState = TaskStateBase & {
  type: 'local_agent'
  agentId: string
  prompt: string
  selectedAgent?: AgentDefinition
  agentType: string
  model?: string
  abortController?: AbortController
  error?: string
  result?: AgentToolResult
  progress?: AgentProgress     ← { toolUseCount, tokenCount, lastActivity, ... }
  isBackgrounded: boolean
  pendingMessages: string[]    ← SendMessage 排队的消息
  retain: boolean              ← UI 是否保持此任务（查看 transcript）
  diskLoaded: boolean          ← 磁盘日志是否已加载
  evictAfter?: number          ← 自动驱逐时间戳
}

进度追踪:
├── ProgressTracker: { toolUseCount, latestInputTokens, cumulativeOutputTokens, recentActivities }
├── updateProgressFromMessage(tracker, message) → 从 API 响应提取进度
│   ├── input_tokens → 保留最新值（累积）
│   ├── output_tokens → 累加
│   └── tool_use → toolUseCount++ + recentActivities.push()
└── getProgressUpdate(tracker) → { toolUseCount, tokenCount, lastActivity }

关键操作:
├── registerAsyncAgent() → 注册后台 agent
├── completeAsyncAgent() → 标记完成 + 通知
├── failAsyncAgent() → 标记失败 + 通知
├── killAsyncAgent() → 中止 + 标记 killed
├── updateAgentProgress() → 更新进度
├── queuePendingMessage() → 排队消息（SendMessage）
├── appendMessageToLocalAgent() → 追加消息到 transcript
├── drainPendingMessages() → 清空排队消息
├── enqueueAgentNotification() → 通知主线程
│   ├── 原子设置 notified 标记（防重复）
│   ├── abortSpeculation() → 中止推测执行
│   └── enqueuePendingNotification() → 排队通知
├── registerAgentForeground/unregisterAgentForeground → 前台管理
└── backgroundAgentTask() → 前台→后台
```

## 六、任务生命周期状态机

```
                    ┌──────────┐
                    │ created  │
                    └────┬─────┘
                         │
                    ┌────▼─────┐
                    │ pending  │
                    └────┬─────┘
                         │
                    ┌────▼─────┐         ┌──────────┐
                    │ running  │────────►│ killed   │
                    └────┬─────┘  abort  └──────────┘
                    │    │
              ┌─────┘    └─────┐
              ▼                ▼
        ┌──────────┐    ┌──────────┐
        │completed │    │  failed  │
        └──────────┘    └──────────┘

InProcessTeammate 额外状态:
        running → idle (等待消息) → running (收到消息)

任务驱逐:
├── 终端状态 (completed/failed/killed) → 设置 evictAfter
├── evictAfter = Date.now() + PANEL_GRACE_MS (30s)
├── 30s 后 → evictTerminalTask() → 从 AppState.tasks 移除
└── UI 有 30s 窗口查看已完成任务的结果
```

## 七、关键设计决策

### 决策 1: 7 种任务类型的联合类型
**做法**: `TaskState = LocalShellTask | LocalAgentTask | RemoteAgentTask | ...`
**原因**: 每种任务有不同的状态字段和生命周期。联合类型 + 类型守卫 (`isLocalAgentTask`) 提供类型安全的任务处理。

### 决策 2: 进程内 vs 进程外隔离
**做法**: tmux/iTerm2 (进程外) + InProcess (进程内) 两种模式
**原因**:
- 进程外: 完全隔离（不同 PID、不同内存），但需要终端工具
- 进程内: 轻量高效（共享 Node.js 进程），适合 SDK/headless

### 决策 3: AsyncLocalStorage 上下文隔离
**做法**: 进程内 teammate 使用 Node.js AsyncLocalStorage
**原因**: 多个 teammate 共享同一进程但需要独立的上下文（CWD、agent ID、权限）。AsyncLocalStorage 提供协程级隔离。

### 决策 4: Mailbox 文件系统通信
**做法**: teammate 权限请求通过文件系统 mailbox 传递
**原因**: tmux 模式下 teammate 是独立进程，不能直接共享内存。文件系统 mailbox 是最可靠的跨进程通信方式。

### 决策 5: 协调器模式的工具分离
**做法**: 主线程只能用 Agent/TaskStop/SendMessage，工作线程只能用 Bash/Read/Edit
**原因**: 主线程负责"思考和分配"，工作线程负责"执行"。分离防止主线程直接操作文件（应通过工作线程），也防止工作线程生成新的 agent（应由主线程决定）。

### 决策 6: Stall 看门狗
**做法**: 后台 shell 命令 45s 无输出 + 最后一行像交互提示 → 通知
**原因**: 模型可能运行需要用户输入的命令（如 `npm init`）而不知道它在等待输入。看门狗检测这种情况并通知模型，避免无限挂起。
