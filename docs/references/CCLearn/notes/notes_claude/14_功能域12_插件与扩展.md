### 文件 1: `utils/plugins/pluginLoader.ts` (3302行) — 插件加载器

**角色**: 从多种来源**发现、缓存、加载**插件。

#### 插件目录结构

```
~/.claude/plugins/                          ← 主插件目录
├── installed_plugins.json                   ← 安装元数据 (V2格式)
├── known_marketplaces.json                  ← 市场注册表
├── marketplaces/                            ← 市场缓存
│   ├── my-marketplace.json                  ← URL 市场缓存
│   └── github-marketplace/                  ← Git 市场克隆
│       └── .claude-plugin/
│           └── marketplace.json
└── cache/                                   ← 插件缓存
    └── {marketplace}/                       ← 按市场分组
        └── {plugin}/                        ← 按插件名分组
            └── {version}/                   ← 版本化目录
                ├── plugin.json              ← 可选的插件清单
                ├── commands/                ← 斜杠命令 (.md)
                ├── skills/                  ← 技能文件 (.md)
                ├── agents/                  ← Agent 定义 (.md)
                ├── hooks/                   ← Hook 配置 (.json)
                ├── mcp.json                 ← MCP 服务器配置
                └── output-styles/           ← 输出样式
```

#### 插件发现来源（优先级顺序）

```
loadAllPlugins() / loadAllPluginsCacheOnly():
│
├── [来源 1] 内置插件 (Built-in)
│   └── builtinPlugins.ts → getBuiltinPlugins()
│       ├── 格式: name@builtin
│       └── 随 CLI 发布，用户可启用/禁用
│
├── [来源 2] 市场插件 (Marketplace)
│   ├── settings.json → enabledPlugins: { "plugin@marketplace": true }
│   ├── 查找: marketplaceManager → getPluginById → 市场条目
│   ├── 解析: resolvePluginPath(pluginId, version)
│   │   ├── 1. 版本化路径: cache/{marketplace}/{plugin}/{version}/
│   │   ├── 2. 种子缓存: CLAUDE_CODE_PLUGIN_SEED_DIR 预装
│   │   └── 3. 遗留路径: cache/{plugin}/ (向后兼容)
│   └── 加载: loadPluginFromPath(path)
│
├── [来源 3] 内联插件 (Inline / --plugin-dir)
│   └── CLI --plugin-dir flag → 会话级临时插件
│
├── [来源 4] 托管插件 (Managed)
│   └── policySettings → enabledPlugins → 企业强制安装
│
└── [来源 5] add-dir 插件
    └── 通过 /add-dir 添加的额外目录中的插件
```

#### 插件加载流程

```
loadAllPlugins():
│
├── [1] 收集所有启用的插件 ID
│   ├── settings.enabledPlugins → { "plugin@marketplace": true }
│   ├── 合并: user + project + local + managed + inline + addDir
│   └── 过滤: isPluginBlockedByPolicy() → 移除被策略阻止的
│
├── [2] 为每个插件 ID:
│   │
│   ├── [2a] 内置插件？
│   │   └── 直接从 BUILTIN_PLUGINS Map 获取
│   │
│   ├── [2b] 解析市场条目
│   │   ├── parsePluginIdentifier(id) → { name, marketplace }
│   │   ├── getPluginByIdCacheOnly(id) → PluginMarketplaceEntry
│   │   └── 无条目 → 尝试直接路径加载
│   │
│   ├── [2c] 版本解析
│   │   ├── calculatePluginVersion(entry, path)
│   │   │   ├── NPM: entry.version (semver)
│   │   │   ├── Git: HEAD SHA (短 hash)
│   │   │   └── 本地: 文件内容 hash
│   │   └── version → 版本化缓存路径
│   │
│   ├── [2d] 缓存管理
│   │   ├── 版本化路径存在？ → 直接使用
│   │   ├── 种子缓存存在？ → 复制到版本化路径
│   │   ├── ZIP 缓存存在？ → 解压到版本化路径
│   │   └── 都不存在 → cachePlugin() → Git clone / NPM download
│   │
│   ├── [2e] 加载清单
│   │   ├── loadPluginManifest(path)
│   │   │   ├── 读取 plugin.json
│   │   │   ├── PluginManifestSchema.parse(data)
│   │   │   └── 返回 PluginManifest
│   │   └── 无 plugin.json → 从目录结构推断
│   │
│   └── [2f] 组装 LoadedPlugin
│       {
│         name, manifest, path, source,
│         repository: "plugin@marketplace",
│         version, components: PluginComponent[]
│       }
│
├── [3] 验证
│   ├── verifyAndDemote(plugins) → 依赖检查
│   ├── 重复名称检测 → 保留优先级高的
│   └── 收集错误 → PluginError[]
│
└── [4] 返回 PluginLoadResult
    {
      enabled: LoadedPlugin[],
      disabled: LoadedPlugin[],
      errors: PluginError[]
    }
```

### 文件 2: `utils/plugins/marketplaceManager.ts` (2643行) — 市场管理

**角色**: 管理插件市场的**注册、缓存、更新**。

#### 市场源类型

```
MarketplaceSource:
├── URL: "https://example.com/marketplace.json"
├── Git: "https://github.com/org/marketplace"
├── 本地目录: "/path/to/marketplace/"
├── 本地文件: "/path/to/marketplace.json"
└── npm: (通过市场条目引用)
```

#### 核心函数

```
=== 注册 ===
addMarketplaceSource(name, source, scope)     ← 添加市场
removeMarketplace(name)                        ← 删除市场
updateMarketplace(name?)                       ← 更新市场（git pull / re-fetch）
loadKnownMarketplacesConfig()                  ← 读取 known_marketplaces.json

=== 查询 ===
getMarketplace(name)                           ← 获取市场清单
getPluginById(pluginId)                        ← 按 ID 查找插件条目
getPluginByIdCacheOnly(pluginId)               ← 只从缓存查找
listAvailablePlugins()                         ← 列出所有可安装插件

=== 缓存 ===
cacheMarketplace(name, source)                 ← 下载/克隆市场
  ├── URL → axios.get → JSON → 写入 marketplaces/{name}.json
  ├── Git → git clone --depth 1 → marketplaces/{name}/
  └── 本地 → 读取本地文件/目录
refreshMarketplace(name)                       ← 刷新市场缓存
  ├── Git → git pull
  └── URL → 重新下载

=== 安全 ===
validateOfficialNameSource(name, source)       ← 验证官方市场名不被仿冒
isSourceAllowedByPolicy(source)                ← 检查策略是否允许
isSourceInBlocklist(source)                    ← 检查阻止列表
```

#### 市场文件结构

```
known_marketplaces.json (KnownMarketplacesFile):
{
  "version": 2,
  "marketplaces": {
    "my-marketplace": {
      "source": "https://github.com/org/marketplace",
      "scope": "user",
      "updatedAt": "2026-01-01T00:00:00Z",
      "autoUpdate": true,
      "sparse": ["plugins/"]  // Git sparse checkout
    },
    "claude-code-marketplace": {
      "source": "https://api.anthropic.com/...",
      "scope": "user",
      "autoUpdate": true
    }
  }
}

marketplace.json (PluginMarketplace):
{
  "name": "My Marketplace",
  "description": "Plugin collection",
  "plugins": {
    "my-plugin": {
      "name": "My Plugin",
      "description": "Does things",
      "version": "1.2.3",
      "source": "https://github.com/org/my-plugin",
      "category": "tools",
      "tags": ["git", "testing"],
      "commands": { "my-cmd": { "description": "A command" } }
    }
  }
}
```

### 文件 3: `utils/plugins/schemas.ts` (1681行) — Schema 定义

**角色**: 所有插件相关的 Zod schema 和类型。

```
核心 Schema:

PluginManifestSchema:           ← plugin.json 验证
├── name, description, version
├── commands: Record<name, CommandMetadata>
├── hooks: HooksSettings
├── mcpServers: Record<name, McpServerConfig>
├── agents: Record<name, AgentMetadata>
├── outputStyles: Record<name, OutputStyleMetadata>
├── dependencies: string[]      ← 插件依赖
├── strict: boolean             ← 严格模式（API 参数遵循）
└── options: PluginOptionSchema[] ← 用户可配置选项

PluginMarketplaceSchema:        ← marketplace.json 验证
├── name, description
├── plugins: Record<id, PluginMarketplaceEntry>
│   ├── name, description, version
│   ├── source: string (Git URL / npm package)
│   ├── category, tags
│   └── commands: Record<name, CommandMetadata>
└── strict: boolean

PluginMarketplaceEntrySchema:   ← 单个插件条目
├── name, description
├── source: string
├── version?: string
├── category?, tags?
├── commands?, agents?, hooks?, mcpServers?
├── dependencies?: string[]
└── strict?: boolean

InstalledPluginsFileSchemaV2:    ← installed_plugins.json
├── version: 2
└── plugins: Record<pluginId, PluginInstallationEntry[]>
    └── scope, path, version, installedAt, updatedAt

PluginIdSchema:                 ← 插件 ID 验证
└── "name@marketplace" 格式

PluginHooksSchema:              ← 插件钩子
├── PreToolUse / PostToolUse / Stop / ...
└── 每个钩子: matcher + hooks[]

安全防护:
├── ALLOWED_OFFICIAL_MARKETPLACE_NAMES → 官方保留名
├── BLOCKED_OFFICIAL_NAME_PATTERN → 仿冒检测正则
├── NON_ASCII_PATTERN → 同形字攻击检测
└── isBlockedOfficialName(name) → 是否被阻止
```

### 文件 11: `services/plugins/pluginOperations.ts` (1088行)

**角色**: 插件的**安装、卸载、启用、禁用、更新**操作。

```
=== 安装 ===
installPluginOp(pluginId, scope, opts):
├── parsePluginIdentifier(pluginId) → { name, marketplace }
├── 检查策略阻止: isPluginBlockedByPolicy()
├── 查找市场条目: getPluginById()
├── 解析版本: calculatePluginVersion()
├── 安装到缓存: installResolvedPlugin()
│   ├── Git → git clone + checkout version
│   ├── NPM → npm pack + extract
│   └── 本地 → 复制目录
├── 注册安装: addPluginInstallation()
├── 启用: updateSettingsForSource(scope, enabledPlugins)
└── clearAllCaches()

=== 卸载 ===
uninstallPluginOp(pluginId, scope, opts):
├── 禁用: updateSettingsForSource → enabledPlugins[id] = false
├── 移除安装记录: removePluginInstallation()
├── 标记缓存为孤立: markPluginVersionOrphaned()
│   └── 后台清理会删除孤立版本
├── 可选: deletePluginDataDir() (--keep-data 保留)
└── 可选: deletePluginOptions() (清除用户配置)

=== 启用/禁用 ===
enablePluginOp(pluginId, scope):
├── 内置插件 → updateSettingsForSource(scope, enabledPlugins[id] = true)
└── 市场插件 → 同上 + 检查是否已安装

disablePluginOp(pluginId, scope):
└── updateSettingsForSource(scope, enabledPlugins[id] = false)

=== 更新 ===
updatePluginOp(pluginId, scope):
├── 查找当前版本: getPluginInstallationFromV2()
├── 计算最新版本: calculatePluginVersion()
├── 版本比较: 相同 → 无需更新
├── 安装新版本: installResolvedPlugin()
├── 更新安装记录: updateInstallationPathOnDisk()
├── 标记旧版本为孤立
└── clearAllCaches()

=== 作用域 ===
VALID_INSTALLABLE_SCOPES = ['user', 'project', 'local']
VALID_UPDATE_SCOPES = ['user', 'project', 'local', 'managed']
```

## 四、插件安全模型

```
插件安全分层:

[层 1] 市场名称保护
├── ALLOWED_OFFICIAL_MARKETPLACE_NAMES → 官方保留名
├── BLOCKED_OFFICIAL_NAME_PATTERN → 仿冒检测
├── NON_ASCII_PATTERN → 同形字攻击
└── isBlockedOfficialName() → 阻止注册

[层 2] 来源策略
├── isSourceAllowedByPolicy(source) → 企业白名单
├── isSourceInBlocklist(source) → 全局黑名单
├── getBlockedMarketplaces() → 被阻止的市场
└── getStrictKnownMarketplaces() → 严格模式（只允许已知）

[层 3] 插件策略
├── isPluginBlockedByPolicy(pluginId) → 企业级阻止
├── pluginPolicy.ts → 策略引擎
└── 托管设置可覆盖用户设置

[层 4] 路径验证
├── validatePathWithinBase(path, base) → 防路径遍历
├── 路径净化: 移除 /../ 等
└── 沙箱化: 插件只能访问自己的目录

[层 5] 依赖安全
├── verifyAndDemote(plugins) → 依赖验证
├── 循环依赖检测
└── 缺失依赖 → 降级（加载但警告）

[层 6] 版本固定
├── calculatePluginVersion() → Git SHA / npm version
├── installed_plugins.json 记录精确版本
└── 防止供应链攻击（版本锁定）
```

## 五、关键设计决策

### 决策 1: 市场+插件分离
**做法**: 市场是插件的"目录"，插件是实际的功能代码
**原因**: 一个市场包含多个插件。分离让用户可以添加一个市场源，然后从中选择安装特定插件。

### 决策 2: 版本化缓存
**做法**: `cache/{marketplace}/{plugin}/{version}/` 目录结构
**原因**: 同一插件可能有多个版本同时存在（不同项目用不同版本）。版本化防止冲突，也支持回滚。

### 决策 3: 安装是全局的，启用是项目级的
**做法**: `installed_plugins.json`（全局）vs `settings.json`（项目级 enabledPlugins）
**原因**: 磁盘上的插件缓存是全局共享的（减少重复下载），但不同项目可能需要不同的插件集。

### 决策 4: 种子缓存 (CLAUDE_CODE_PLUGIN_SEED_DIR)
**做法**: 支持预装的插件种子目录
**原因**: BYOC（Bring Your Own Container）环境中，容器构建时预装插件到种子目录，运行时直接复制到版本化缓存，避免运行时的网络下载。

### 决策 5: 官方市场名称保护
**做法**: 正则 + 白名单 + 同形字检测 阻止仿冒
**原因**: 防止第三方注册 "anthropic-marketplace" 或 "clаude-plugins"（注意 Cyrillic 'а'）来分发恶意插件。

### 决策 6: MCPB（MCP Bundle）支持
**做法**: 二进制打包格式，包含 MCP 服务器可执行文件
**原因**: 某些 MCP 服务器需要原生二进制（不是 Node.js），MCPB 格式让插件可以分发编译好的服务器。
