Claude Code Memory 架构 · 四大子系统全景

SessionMemory · Durable memdir · Extract / AutoDream · TeamMemorySync —— 从 session 检索到 durable 持久化再到团队协作共享的完整记忆闭环

FRAMEWORK 01
SessionMemory / Relevant Retrieval

当前会话如何组织短期记忆,并从 durable memory 中按相关度拉回候选注入下一轮 prompt

① Session 输入
Layer 01 · 会话流
运行中的 messages / tools / attachments
当前 session 持续产生消息、工具调用与附件,构成短期记忆的原料流
session runtime stream
② Session 服务
Layer 02 · 主服务
SessionMemory 主服务
组织当前 session 记忆,为 query/compact/restore 提供 session 级别视图
services/SessionMemory/sessionMemory.ts
Layer 03 · 辅助与 prompt
Utils 与 prompt 模板
做筛选、格式化、协同计算,并为子流程提供 prompt 模板
sessionMemoryUtils.ts · prompts.ts
③ 检索中枢
Layer 04 · 核心
findRelevantMemories 检索入口
从 durable memory 里按相关度检索最匹配的候选,是注入 query 的关键入口
memdir/findRelevantMemories.ts
关键特征
不是全文搜索壳
带 freshness 打分与候选筛选的 retrieval 流程,session 语义与 durable 候选在此汇合
relevance · freshness · ranking
④ memdir 支撑
Layer 05 · 扫描
memoryScan 候选产出
扫描 memory 文件并产出候选集,为上层 retrieval 提供原料
memdir/memoryScan.ts
Layer 06 · 时效/类型
memoryAge 与 memoryTypes
提供 time-based relevance 支持,并定义 retrieval 层的数据类型契约
memoryAge.ts · memoryTypes.ts
Layer 07 · 底层
memdir 目录服务
durable memory 的底层读写与内容访问,为扫描与检索提供基础能力
memdir/memdir.ts
⑤ 回注 query
Layer 08 · 输出
相关 memories 回注
筛选结果以 attachments / prompts 形式回到下一轮 query,形成检索闭环
query · attachments · prompts
关键结论
SessionMemory ≠ Durable
两者是不同层,retrieval 是它们之间的汇合点而非等价关系
two-layer memory model
会话流→ Session 服务→ 检索中枢→ memdir 底层→ 回注 query
FRAMEWORK 02
Durable memdir / Paths / Versions

长期记忆存在哪、安全如何保证、文件格式如何受控演进,以及 worktree 间的共享策略

① 配置源
Layer 01 · 入口
settings / env / project root
从配置、环境变量与项目根共同决定 memory 根目录的来源
settings · env · project root
② 路径安全边界
Layer 02 · 边界
paths 路径解析与校验
决定 memory 根、校验路径安全、仅 trusted settings 可 override,是安全边界而非普通配置
memdir/paths.ts
关键特征
worktree-shared root
让同仓多工作树共用同一份长期记忆,避免分裂与重复抽取
shared across worktrees
③ memdir 核心
Layer 03 · 核心
memdir 主服务
durable memory 的目录主服务,负责 memory 文件访问与基础读写
memdir/memdir.ts
④ 类型与版本
Layer 04 · 类型
memory types 定义
durable memory 的领域类型与 memdir 层自身的类型定义,两套契约共同支撑
utils/memory/types.ts · memdir/memoryTypes.ts
Layer 05 · 版本
versions 兼容性
让 memory 文件格式可以受控演进,而非随便追加落文本
utils/memory/versions.ts
Layer 06 · 识别
memoryFileDetection
识别哪些文件属于 memory 文件,支撑扫描、读写与注入流程
utils/memoryFileDetection.ts
⑤ 被复用
Layer 07 · 输出
被上层复用
SessionMemory / extract / autoDream / teamMemory 都基于同一套 memdir 构建
session · extract · dream · team
关键结论
两套持久化层
durable memory 与 session transcript 是完全不同的持久化层,不可混同
durable ≠ transcript
配置源→ 路径边界→ memdir 核心→ 类型/版本→ 被复用
FRAMEWORK 03
extractMemories / AutoDream / Consolidation

从会话中生成 durable 记忆,再通过 autoDream 周期性整理浓缩,让记忆成为持续演化的资产

① 会话收尾
Layer 01 · 触发
session 结束阶段
当前对话走到收尾,触发从短期信息到长期记忆的转化流程
session end lifecycle
② 记忆抽取
Layer 02 · 抽取主逻辑
extractMemories 主服务
从会话中抽取 durable memory 条目,把短期信息转成长期记忆
services/extractMemories/extractMemories.ts
Layer 03 · prompt
extract prompt 模板
抽取阶段使用的 prompt 模板,决定哪些信息被识别为值得留存
extractMemories/prompts.ts
③ 整理中枢
Layer 04 · 核心
autoDream 整理主逻辑
对已有 memories 做 consolidation/dream,进一步整理、压缩与重组
services/autoDream/autoDream.ts
Layer 05 · 并发/配置/提示
lock · config · prompt
consolidation 锁避免并发整理冲突,配置与 prompt 模板支撑浓缩逻辑
consolidationLock.ts · config.ts · consolidationPrompt.ts
④ 持久化
Layer 06 · 存储
memdir durable storage
整理后的结果写入 durable memory,等待下一次 relevant retrieval 再回到 query
memdir/**
Layer 07 · 治理路径
sessionMemoryCompact
说明 memory 不只用于 retrieval,也被用于 compact 治理路径
services/compact/sessionMemoryCompact.ts
⑤ 相邻建议系统
Layer 08 · 建议
PromptSuggestion 主逻辑
与会话收尾和后续建议相关的系统,与 memory 收尾治理相邻而非合并
services/PromptSuggestion/promptSuggestion.ts
Layer 09 · 推测
speculation 辅助
prompt suggestion 的 speculation 辅助逻辑,与 memory 治理协同工作
PromptSuggestion/speculation.ts
会话收尾→ 抽取→ 整理浓缩→ 持久化→ 相邻建议
