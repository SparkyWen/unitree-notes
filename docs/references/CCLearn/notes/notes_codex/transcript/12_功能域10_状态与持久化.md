## 三、核心文件逐一分析

### 文件 1: `state/store.ts` (35行) — 极简状态管理

**角色**: 整个 Claude Code 的**状态管理核心**。只有 35 行。

```typescript
type Listener = () => void
type OnChange<T> = (args: { newState: T; oldState: T }) => void

type Store<T> = {
  getState: () => T
  setState: (updater: (prev: T) => T) => void
  subscribe: (listener: Listener) => () => void
}

function createStore<T>(initialState: T, onChange?: OnChange<T>): Store<T> {
  let state = initialState
  const listeners = new Set<Listener>()

  return {
    getState: () => state,
    setState: (updater) => {
      const prev = state
      const next = updater(prev)
      if (Object.is(next, prev)) return  // 引用相等 → 跳过
      state = next
      onChange?.({ newState: next, oldState: prev })
      for (const listener of listeners) listener()
    },
    subscribe: (listener) => {
      listeners.add(listener)
      return () => listeners.delete(listener)
    },
  }
}
```

**关键设计**:
- **不可变更新**: `setState` 接受 `(prev) => next` updater，不是直接赋值
- **引用相等跳过**: `Object.is(next, prev)` → 避免无效重渲染
- **onChange 钩子**: 每次状态变化通知外部（用于 CCR 同步、设置持久化）
- **无依赖**: 不依赖 React/Redux/Zustand — 纯 TypeScript

### 文件 4: `state/onChangeAppState.ts` (~180行) — 变更监听

**角色**: 状态变更的**副作用处理器**。

```
onChangeAppState({ newState, oldState }):
│
├── [1] 权限模式变更检测
│   ├── prevMode !== newMode
│   ├── 外部化: toExternalPermissionMode() (auto→default, bubble→default)

│   │   ├── notifySessionMetadataChanged() → CCR external_metadata 同步

│       ├── saveGlobalConfig({ permissionMode: newExternal })
│       └── setMainLoopModelOverride() (如果模式影响模型)

├── [2] 模型变更检测
│   ├── prevModel !== newModel
│   ├── 持久化: updateSettingsForSource('userSettings', { model: newModel })
│   └── 重应用环境变量: applyConfigEnvironmentVariables()
│
├── [3] 设置变更检测
│   ├── prevSettings !== newSettings
│   └── 传播到需要的位置

└── [4] Bridge 模式同步
```

```
├── 验证: 确保所有必需字段存在
├── configCache = result → 缓存
├── insideGetConfig = false
```

## 五、关键设计决策

### 决策 1: 35行极简 Store 而非 Redux/Zustand
**做法**: `createStore` 只有 getState/setState/subscribe 三个方法
**原因**: Claude Code 不需要中间件、时间旅行、devtools。`useSyncExternalStore` 原生支持 React 18 并发模式。35 行覆盖所有需求。

### 决策 2: 双层状态（bootstrap + AppState）
**做法**: bootstrap/state.ts (进程级) + AppStateStore (会话级)
**原因**:
- bootstrap 不依赖 React → 可在 init/query/tools 中任意使用
- AppState 触发 React 渲染 → 只放 UI 需要的状态
- 两者通过 onChangeAppState 同步

### 决策 3: JSONL 追加日志
**做法**: 对话历史以 `.jsonl` 追加（不是覆写 JSON）
**原因**:
- 追加写入是原子的（即使断电也不会损坏已写入的行）
- 增量追加比全量覆写快得多（长对话可能有 MB 级数据）
- JSONL 格式可以流式解析（不需要整个文件在内存中）

### 决策 4: 文件锁保护配置写入
**做法**: `saveGlobalConfig` 使用 lockfile
**原因**: 多个 Claude Code 实例可能同时运行（不同终端/IDE）。锁保证原子读-改-写。

### 决策 5: 配置递归防护
**做法**: `insideGetConfig` 布尔守卫
**原因**: `getGlobalConfig → logEvent → GrowthBook → getGlobalConfig` 会无限递归。守卫在递归时返回默认配置。

### 决策 6: onChangeAppState 集中副作用
**做法**: 所有状态变更副作用在一个函数中处理
**原因**: 之前 8+ 个变更路径中 6 个忘了同步 CCR/SDK。单一 onChange 入口消除了这类遗漏。
