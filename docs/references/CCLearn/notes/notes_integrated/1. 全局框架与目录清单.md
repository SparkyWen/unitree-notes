补充解释：

### 1. Bridge 模式的设计目的

这个 bridge 是 Claude Code 的**第二入口**，和 REPL 并列存在，解决的是一个根本性的问题：

> **同一套核心逻辑，需要服务两种完全不同的调用者**

Bridge 的作用就是**在 query() 和宿主程序之间架一层干净的 JSON 协议**，让编辑器插件可以：

1. 通过 stdin 发送指令（用户消息、工具结果确认）
2. 通过 stdout 接收结构化事件（assistant 消息、工具调用请求、状态变化）
3. 完全不需要渲染任何 UI


### 2. 两种模式对比

|          | REPL 模式              | Bridge 模式                     |
| -------- | ---------------------- | ------------------------------- |
| 调用者   | 人类用户               | 外部程序（IDE插件、编辑器扩展） |
| 交互方式 | 键盘输入 / Ink 渲染 UI | stdin/stdout 消息协议（JSON）   |
| 生命周期 | 用户手动退出           | 宿主程序控制                    |
| 典型场景 | 终端直接用             | VS Code 扩展、JetBrains 插件    |

### 3. 各文件职责

```
bridge/bridgeMain.ts      ← 入口：识别是否以 bridge 模式启动，初始化管道
bridge/sessionRunner.ts   ← 核心：无头执行 query()，跳过所有 Ink UI 渲染
bridge/replBridge.ts      ← 协议层：把 REPL 的事件流序列化成 JSON 消息
bridge/codeSessionApi.ts  ← API层：暴露给宿主程序的结构化接口
```

## 4. 关键架构设计

### 模式1：Feature Gates（特性门控）

```typescript
import { feature } from 'bun:bundle'
// 编译时死代码消除 — 外部构建不包含 Ant 内部功能
if (feature('BRIDGE_MODE')) { /* ... */ }
if (feature('KAIROS')) { /* ... */ }
```

**贯穿整个代码库**。用于区分 ==Anthropic 内部功能和外部发布版本==。

### 模式2：延迟动态导入

```typescript
// main.tsx / cli.tsx 大量使用
const { bridgeMain } = await import('../bridge/bridgeMain.js')
```

**目的**：==最小化启动时模块加载==。`--version` 快速路径零导入。

### 模式3：buildTool() 工厂

```typescript
export const BashTool = buildTool({
  name: 'bash',
  schema: z.object({ command: z.string() }),
  execute: async (params, context) => { /* ... */ }
})
```

每个工具是独立目录，统一接口。

### 模式4：AsyncGenerator 查询循环

```typescript
export async function* query(params): AsyncGenerator<StreamEvent | Message, Terminal> {
  // yield 每个中间事件 → 调用方（REPL/print）逐个消费并渲染
}
```

`query()` 是异步生成器，yield stream 事件和消息。REPL 和 print 模式分别消费。

### 模式5：React + Ink 终端 UI

```
App (components/App.tsx)
  └── REPL (screens/REPL.tsx)
       ├── PromptInput (输入框)
       ├── Messages (消息列表)
       ├── StatusLine (状态栏)
       └── 各种 Dialog (权限、设置等)
```

完全使用 React 组件模型构建终端 UI，自定义 Ink 分支提供渲染。

  sessionId: SessionId
