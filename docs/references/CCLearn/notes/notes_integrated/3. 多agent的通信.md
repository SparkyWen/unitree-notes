
# 1. Claude Code 里的多 agent 通信不是单一通道，而是 5 条并存的机制

Claude Code 里的 agent-to-agent 通信，并不是简单“一个 agent 调另一个 agent 的函数”。

实际至少有 5 条机制并存：

1. **Tool-level orchestration**
   - 通过 `AgentTool` / `Task*Tool` / `Team*Tool` / `SendMessageTool`
   - 由主 agent 显式创建、分派、查询、停止、发消息

2. **Task-centric communication**
   - 通过 task create/get/list/update/output/stop
   - agent 之间不是直接共享内存，而是通过 task 这个中间对象协作

3. **Mailbox / queued message communication**
   - 通过 mailbox、queued messages、bridge mailbox、attachment 注入
   - 让 agent 或远程/桥接端可以异步收到消息或任务通知

4. **Swarm / teammate backend communication**
   - 通过 in-process、tmux、iTerm、pane backend 等后端
   - leader/worker 协作，附带 permission sync / reconnection / layout

5. **Bridge / remote communication**
   - 通过 bridgeMessaging、remotePermissionBridge、sessionRunner、sessionStorage
   - 支撑跨设备/跨进程/远端 agent 会话

也就是说：

> **Claude Code 的多 agent 通信，本质上是“任务对象 + mailbox + runtime backend + permission bridge + memory sync”的复合系统。**

# 3. 多agent具体如何实现通信的？

## 3.1 路径一：通过 AgentTool 进行“创建与控制”

主 agent 并不是直接拿到另一个 agent 的对象引用，而是通过：

- `AgentTool.tsx`
- `forkSubagent.ts`
- `runAgent.ts`
- `resumeAgent.ts`
- `spawnMultiAgent.ts`

来做到：

- 创建子 agent
- 恢复已有 agent
- 多 agent 并发生成

这条链更像：

```text
leader agent
  -> AgentTool
  -> spawn/fork/resume agent runtime
  -> 返回 agent 句柄 / 任务引用 / 状态
```

这不是传统 OO 式“直接方法调用”，而是运行时调度。

---

## 3.2 路径二：通过 Task 这个中介对象协作

这是多 agent 通信里最重要的一层之一。

相关工具：

- `TaskCreateTool`
- `TaskGetTool`
- `TaskListTool`
- `TaskUpdateTool`
- `TaskStopTool`
- `TaskOutputTool`

含义是：

- agent A 不一定直接给 agent B 发一段消息
- 更常见的是：
  - A 创建 task
  - B 处理 task
  - A 查询/更新/停止 task
  - 输出通过 task output 回流

也就是：

> **task 是 Claude Code 多 agent 通信里的“共享任务对象 / 协作总线”。**

---

## 3.3 路径三：通过 SendMessageTool / mailbox 做显式消息传递

相关文件：

- `SendMessageTool.ts`
- `context/mailbox.tsx`
- `context/QueuedMessageContext.tsx`
- `utils/mailbox.ts`
- `utils/teammateMailbox.ts`
- `hooks/useMailboxBridge.ts`

这条链意味着：

- agent 间可以存在显式 message passing
- 消息不一定立即同步到对方上下文，而是进入 mailbox / queue
- 再由 runtime/bridge/hook 把它注入目标 agent 会话或 UI

也就是：

> **Claude Code 有真正的 agent mailbox 概念，不是只有 task。**

---

## 3.4 路径四：通过 swarm backend 做 leader/worker 协作

相关文件：

- `utils/swarm/backends/**`
- `utils/swarm/inProcessRunner.ts`
- `utils/swarm/spawnInProcess.ts`
- `utils/swarm/leaderPermissionBridge.ts`
- `utils/swarm/permissionSync.ts`
- `utils/swarm/reconnection.ts`
- `utils/swarm/teamHelpers.ts`
- `utils/swarm/teammateInit.ts`
- `utils/swarm/teammateLayoutManager.ts`
- `utils/swarm/teammateModel.ts`
- `utils/swarm/teammatePromptAddendum.ts`

这说明多 agent 不是只有逻辑层“多个会话”，还有后端执行层：

- in-process backend
- tmux backend
- iTerm backend
- pane executor backend

这条链里，通信除了任务和消息，还有：

- permission sync
- reconnection
- teammate layout
- teammate mode snapshot

所以 swarm 模式下的 agent-to-agent 通信，其实还包含“运行环境与控制面的同步”。

---

## 3.5 路径五：通过 bridge / remote permission bridge 跨会话/跨设备通信

相关文件：

- `bridge/bridgeMessaging.ts`
- `bridge/sessionRunner.ts`
- `remote/remotePermissionBridge.ts`
- `utils/background/remote/remoteSession.ts`
- `utils/background/remote/preconditions.ts`
- `sessionStorage.ts`

当 agent 不在同一进程 / 同一终端环境时：

- 消息
- 任务
- 权限请求
- 状态回流

都可能通过 bridge/remote 层转运。

这时通信就不是纯内存对象，而是：

- bridge messaging
- session runner
- permission bridge
- persisted session transcript / mailbox / storage

---

## 3.6 路径六：通过 shared memory / team memory 进行“间接通信”

相关文件：

- `tools/AgentTool/agentMemory.ts`
- `tools/AgentTool/agentMemorySnapshot.ts`
- `services/teamMemorySync/**`
- `utils/teamMemoryOps.ts`

这不是实时消息，但在多 agent 协作里非常重要：

- agent A 写入 shared/team memory
- agent B 后续通过 retrieval 或 sync 看到这些信息

所以这是一种：

> **非实时、共享状态型 agent 通信。**

```
      ├── AgentTool 创建/恢复子 agent

      │
      ├── TaskCreateTool 创建 task
      │      -> 子 agent 接 task / 更新 task / 输出 task result

      ├── swarm backend 同步
      │      -> permissionSync / leaderPermissionBridge / reconnection
      │
      ├── bridge / remote 层转运
      │      -> bridgeMessaging / sessionRunner / remotePermissionBridge
      │
      └── shared/team memory 间接共享
             -> teamMemorySync / agentMemory / snapshots
```

# 6. 多 agent 通信主骨架文件详细说明

下面先把真正撑起 agent-to-agent 通信的骨架文件讲清楚。

---

## 6.1 `source/src/tools/AgentTool/AgentTool.tsx`

**定位：** 多 agent 调度入口。

**负责：**

- 把“创建/调用 agent”暴露为工具能力
    
- 让 leader agent 可以显式生成、恢复或管理子 agent
    

**一句话总结：**

> 多 agent 系统的顶层调度工具入口。

---

## 6.2 `source/src/tools/AgentTool/forkSubagent.ts`

**定位：** 子 agent fork 路径。

**负责：**

- 真正创建新的 agent 运行分支
    
- 建立与 leader 的关系
    

**一句话总结：**

> 创建 agent-to-agent 协作分支的核心实现。

---

## 6.3 `source/src/tools/AgentTool/runAgent.ts`

**定位：** agent 执行器。

**负责：**

- 真正跑起一个 agent 任务/会话
    
- 驱动其主循环与输出回流
    

**一句话总结：**

> agent runtime 的执行入口。

---

## 6.4 `source/src/tools/shared/spawnMultiAgent.ts`

**定位：** 多 agent spawn 共享编排器。

**负责：**

- 把多 agent 并行生成与调度逻辑抽出来复用
    

**一句话总结：**

> 多 agent 并发生成的共享编排层。

---

## 6.5 `source/src/tools/TaskCreateTool/TaskCreateTool.ts`

**定位：** task 中介对象的创建入口。

**负责：**

- 创建 task
    
- 让 agent 协作从“直接消息”升级成“通过任务对象协同”
    

**一句话总结：**

> 多 agent 协作总线的创建入口。

---

## 6.6 `source/src/tools/SendMessageTool/SendMessageTool.ts`

**定位：** 显式 agent message passing 工具。

**负责：**

- 发送 agent-to-agent 消息
    
- 对接 mailbox/queued message/runtime bridge
    

**一句话总结：**

> agent 显式消息通道入口。

---

## 6.7 `source/src/context/mailbox.tsx` 与 `source/src/context/QueuedMessageContext.tsx`

**定位：** mailbox / queued message 上下文。

**负责：**

- 维护异步消息投递与消费的运行时上下文
    
- 让 agent 消息不是即时函数调用，而是可排队、可异步消费的事件流
    

**一句话总结：**

> 多 agent 异步消息总线的上下文层。

---

## 6.8 `source/src/utils/swarm/leaderPermissionBridge.ts` 与 `permissionSync.ts`

**定位：** leader/worker 权限协同层。

**负责：**

- 在 swarm 多 agent 后端里同步权限状态
    
- 让 worker 的工具请求与 leader 的权限模型对齐
    

**一句话总结：**

> 多 agent 执行环境里权限边界的同步桥。

---

## 6.9 `source/src/bridge/bridgeMessaging.ts`

**定位：** 跨 bridge 的消息层。

**负责：**

- 在 bridge / remote / session runner 场景中转运消息
    
- 让 agent-to-agent 通信可以跨运行环境继续成立
    

**一句话总结：**

> 多 agent 跨进程/跨设备消息转运桥。

---

## 6.10 `source/src/services/teamMemorySync/index.ts`

**定位：** 共享 memory 协作层入口。

**负责：**

- 让 agent 之间除了显式消息外，还能通过 shared memory 间接协作
    

**一句话总结：**

> 多 agent 非实时共享状态通道的入口。

# 7. 最关键的实现结论

## 结论 1：Claude Code 的 agent-to-agent 通信不是单条管道，而是“任务 + 消息 + backend + bridge + memory”五层协作

## 结论 2：最重要的同步协作实体其实不是 message，而是 task

message 更像显式通知/对话； task 则像真正的工作单元和协作对象。

## 结论 3：mailbox 说明 agent 消息在很多场景下是异步事件流，而不是即时调用

## 结论 4：swarm backends 说明多 agent 不只是逻辑概念，还有执行后端层的通信与同步

## 结论 5：team memory / agent memory 说明 Claude Code 还有一条“共享状态型通信”路径

这条路径不是实时消息，但对长期协作非常关键。
